Recorded non-blocking findings and their disposition:

- `STD-01` (low): the mechanical architecture checks in `src/test/architecture.test.ts` enumerate only `src/app` and `src/api`, so a future violation inside the new `src/features/**` production code would not be caught. Current feature code is compliant. Disposition: carried to T08, which must extend the mechanical checks to all production frontend roots, including `src/features`, with a negative fixture.
- `STD-02` (low): the responsive tests are branch-selection proof using jsdom `matchMedia` stubs, not real layout proof. The tests do have falsification power (listed below), but real breakpoint/layout behavior is deferred to browser proof. Disposition: carried to T07 (Gate D, desktop/tablet/mobile viewports).
- `STD-03` (low): static copy "Aging inventory is 91 or more days in stock." restates the backend aging threshold in the frontend. It is display copy only - the frontend does not recompute `isAging` - and no design requirement forbids it. Disposition: accepted low risk, recorded; no repair required.
- `SPEC-F1` (info): on tablet, filters are exposed only through the sheet, whereas System Design 6.4 words tablet as "high-frequency filters visible; additional filters in an adaptive sheet". Requirement RESP-002 and the T04 acceptance bullet both authorize a tablet sheet, so the contract is satisfied at the graded level. Disposition: accepted; no repair required.
