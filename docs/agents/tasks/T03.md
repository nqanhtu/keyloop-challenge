test_seams:
  - Status catalog seam: GET /vehicle-action-statuses returns active statuses dynamically in deterministic sortOrder order while the underlying reference catalog can retain inactive historically referenced identities.
  - Action history seam: GET /vehicles/:vehicleId/actions returns the complete immutable action sequence newest-first with status identity and label plus trusted actor snapshot, timestamp, and optional note.
  - Action creation HTTP seam: POST /vehicles/:vehicleId/actions accepts only statusId and optional note; identity, timestamp, and actor snapshot are generated behind HTTP and the created immutable action is returned.
  - Eligibility seam: action creation distinguishes vehicle missing, not present in the latest snapshot, not aging, status missing, status inactive, and unauthorized trusted context with stable ApiError codes; lifecycle alone is not an eligibility gate.
  - Authorization seam: the default HTTP fixture injects an authorized manager actor through a trusted provider that request-body data cannot override; tests can inject an unauthorized trusted context without implementing roles or an IdP.
  - Persistence seam: a browser-storage-backed action repository survives creation of a fresh repository/service/handler graph over the same storage and preserves actions independently when the inventory projection reader is replaced.
  - Inventory composition seam: the T02 InventoryService receives a real CurrentActionReader backed by the action module so list/detail actionStatusId/currentAction and summary agingWithAction reflect newest persisted actions behind HTTP.
  - Summary seam: GET /inventory/summary derives totalInventory, agingVehicles, agingWithAction, and lastSuccessfulSyncAt from present projections, Aging Policy, current-action interface, and sync metadata without React-side calculation.
  - Architecture seam: app-facing consumers use typed ApiClient functions; browser storage remains inside the mock action persistence adapter and action/status modules do not read inventory projection storage directly.

  - POST /vehicles/:vehicleId/actions accepts statusId plus note omitted, null, empty string, or any string; it rejects unexpected actor, identity, or timestamp ownership from the body rather than trusting or persisting body-supplied values.
