# INC-001 Heavy jsdom integration tests exceed the default Vitest timeout under load

- incident_id: INC-001
- task: T05
- symptom: The required `npm run test` gate intermittently failed with `Test timed out in 5000ms` on full-dashboard jsdom integration tests (T05 `vehicle-detail.test.tsx`, and the T04 `responsive-inventory.test.tsx` / `inventory-dashboard.test.tsx` files) while the same tests passed standalone.
- root_cause: Full-dashboard jsdom render plus RTL `findBy*` interaction tests have a multi-second cost; under concurrent CPU load (host load average ~180-234 on 10 CPUs) individual tests exceeded Vitest 5000 ms default. Several heavy test files declared no explicit timeout and `vitest.config.ts` set no `testTimeout`, so the timing margin was thin. No functional defect was involved.
- classification: verification
- repair: Test-only. Added `testTimeout: 20_000` to `vitest.config.ts` and an explicit 15 s per-test timeout to the 8 heavy dashboard tests in `src/features/actions/vehicle-detail.test.tsx`, matching the existing `INTERACTION_TIMEOUT` in `create-action.test.tsx`. No assertion changed. Committed as `03e69bf`.
- candidate_learning: A repository that runs full-application jsdom integration tests should set an explicit `testTimeout` ceiling at the config level so required validation is load-tolerant instead of relying on the 5000 ms default.
- evidence: `docs/agents/evidence/T05.md`; fresh Standards review finding F1; fresh Standards-recheck and Tester runs reproducing green results under induced CPU load.
